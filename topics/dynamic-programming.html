💎 Dynamic Programming

Optimizing recursive solutions

What is Dynamic Programming?

DP optimizes recursive solutions by storing results of overlapping subproblems. Two approaches: Memoization (top-down) and Tabulation (bottom-up).

Fibonacci - All Approaches

// Naive Recursion - O(2^n)
function fibRecursive(n) {
    if (n <= 1) return n;
    return fibRecursive(n - 1) + fibRecursive(n - 2);
}

// Memoization (Top-down) - O(n)
function fibMemo(n, memo = {}) {
    if (n in memo) return memo[n];
    if (n <= 1) return n;
    
    memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    return memo[n];
}

// Tabulation (Bottom-up) - O(n)
function fibTab(n) {
    if (n <= 1) return n;
    
    const dp = [0, 1];
    for (let i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    
    return dp[n];
}

// Space Optimized - O(1) space
function fibOptimized(n) {
    if (n <= 1) return n;
    
    let prev2 = 0, prev1 = 1;
    for (let i = 2; i <= n; i++) {
        const current = prev1 + prev2;
        prev2 = prev1;
        prev1 = current;
    }
    
    return prev1;
}

Connecting the approaches

  • The naive recursion mirrors the mathematical recurrence but recomputes overlapping subproblems.
  • Memoization caches each result so the recursion tree collapses into O(n) unique calls.
  • Tabulation iteratively builds the array from the base cases, eliminating recursion entirely.
  • The space-optimized version keeps only the last two values because each Fibonacci number depends on just those.

💻 Classic DP Problems

1. Climbing Stairs Easy

You can climb 1 or 2 steps. How many ways to reach n steps?

function climbStairs(n) {
    if (n <= 2) return n;
    
    let prev2 = 1, prev1 = 2;
    for (let i = 3; i <= n; i++) {
        const current = prev1 + prev2;
        prev2 = prev1;
        prev1 = current;
    }
    
    return prev1;
}

Think of it as Fibonacci

  • Each step count depends on the previous two counts (ways to reach step n-1 and n-2).
  • We keep two rolling variables (prev2, prev1) instead of a whole DP array.
  • The loop accumulates the total ways by sliding the window forward.
  • This saves memory while still giving O(n) time.

2. Longest Increasing Subsequence Medium

function lengthOfLIS(nums) {
    const n = nums.length;
    const dp = new Array(n).fill(1);
    
    for (let i = 1; i < n; i++) {
        for (let j = 0; j < i; j++) {
            if (nums[j] < nums[i]) {
                dp[i] = Math.max(dp[i], dp[j] + 1);
            }
        }
    }
    
    return Math.max(...dp);
}

Step-by-step reasoning

  • dp[i] records the LIS ending exactly at index i.
  • For each i, we compare against previous indices j to see if nums[i] can extend their subsequence.
  • The Math.max keeps the best length when multiple j values work.
  • Taking the max of the entire dp array gives the final answer.

3. Coin Change Medium

function coinChange(coins, amount) {
    const dp = new Array(amount + 1).fill(Infinity);
    dp[0] = 0;
    
    for (let i = 1; i <= amount; i++) {
        for (let coin of coins) {
            if (i >= coin) {
                dp[i] = Math.min(dp[i], dp[i - coin] + 1);
            }
        }
    }
    
    return dp[amount] === Infinity ? -1 : dp[amount];
}

Why the table works

  • dp[x] stores the minimum coins needed to build value x.
  • We initialize to Infinity so any real combination will be smaller.
  • For each amount, we try every coin and relax the state with dp[i - coin] + 1.
  • If dp[amount] stays Infinity, we know no combination exists.

📚 Key Takeaways

  • DP optimizes problems with overlapping subproblems
  • Memoization: cache results in recursion
  • Tabulation: build solution bottom-up
  • Identify recurrence relation to solve DP problems
